# E10 / E10b: 出力形式の頑健性(通常JSON・制約付きJSON・選択式・束ね質問)

追加課題(初版の完了条件外)。数値は各実行の `cases.csv`(と `run.json`)から計算したもの(実行後に使い捨てのスクリプトで集計。コミットしていない)。1回測定・小標本なので強い結論にしない。

## 1. 目的

出力形式の崩れやすさ(形式不正)を方式間で比べる。

- **E10(ノイズ)**: 白色ノイズ画像100枚で、選択式・通常JSON・`json_schema`(制約付きデコードのJSON)・束ね質問(rank / Y/N)の形式不正率と時間を測る。温度0では同じ画像の出力は決定的なので、形式不正の確率は「多数の異なる画像」で見る。正解は使わない。実画像の失敗率ではなく、方式間の頑健性の比較。
- **E10b(実データ)**: 実データのデータセット(元画像31枚)で、通常JSONと `json_schema` を比べる。通常JSONで起きていた形式不正が、制約付きデコードでなくなるか、精度・時間がどうなるかを見る。

## 5. 観察(事実)

- **ノイズ画像では、通常JSONは6モデルすべてで失敗0/100**。実画像で JSON の形式不正が出るモデル(E10b の json で 1〜10/31)でも、白色ノイズでは出なかった。つまり、実画像での JSON の形式不正は、画像の内容に依存する。
- ノイズ画像で、束ね質問は小型モデルで大きく崩れた。Qwen 2B Q8 は rank・Y/N とも 100/100、Gemma E2B Q4 は 52・100、Qwen 0.8B Q4 は 28・93、Qwen 2B Q4 は 13・0。Qwen 0.8B Q8 と Qwen 9B は両方とも 0。選択式(1項目ずつ)は全モデル 0/100。
- `json_schema` はノイズで全モデル 0/100。通常JSONに対する時間の差は −48〜+71 ms。
- **実画像(E10b)では、`json_schema` が全5モデルで JSON の形式不正を0にした**(元画像31件: S3 9→0、S5 10→0、S7 7→0、S9 6→0、F1 1→0)。
- 形式不正が消えた分、単一項目の正答率は選択式(reprime の1項目ずつ確認オフ)に近い水準まで上がった(単一5項目平均: S3 63.2→89.7、S5 58.7→83.9、S7 69.0→91.0、S9 74.2→89.7、F1 89.0→91.0。参考の選択式は 90.3・86.5・89.0・87.1・90.3)。キャラの完全一致は S7 で 74.2→96.8、S3 64.5→87.1、S5 45.2→80.6、S9 67.7→83.9、F1 87.1→90.3。
- 服装の完全一致は、json_schema でも選択式(参考。1項目ずつ確認オフ)より低いモデルが残った(json_schema 対 選択式: S3 67.7 対 74.2、S5 54.8 対 48.4(json_schema のほうが高い)、S7 54.8 対 74.2、S9 41.9 対 80.6、F1 93.5 対 90.3)。
- 時間は、S3 で 1039→563 ms(JSON の形式不正の再試行がなくなったため)、S5 695→526、F1 956→917 と短くなり、S7 1020→1067(+47)、S9 704→746(+42)ではわずかに長い(1回測定。数十 ms は区別できない)。

## 6. 限界

- 白色ノイズは実画像とかけ離れている。ここでの失敗率は、実画像の失敗率でも実運用の失敗率でもない。方式間の頑健性の比較(と、ノイズでは通常JSONが崩れなかったという観察)にとどまる。
- 実データは元画像31枚と小標本、各条件1回の測定。少数の差(1〜2件、数十 ms)から強い結論を書かない。
- `json_schema` は enum(候補ラベルの列挙)で値も縛る。**構文だけでなく、取りうる値の集合も制約している**ので、精度の改善には、形式不正を避けた効果と、値を候補内に限った効果の両方が含まれうる。両者は切り分けていない。
- 通常JSONの時間には、形式不正の再試行が含まれる(試行数は `cases.csv` の `json_attempts`)。
- E10b と reprime の選択式・束ね(rank)は別の実行で、コミットも実施日も違う(4.1)。
- モデル構成は小型4種と Qwen 9B(改造版 llama-server)のみ。Gemma 4 12B・未改造版は測っていない。
