# 準備の不公平を直したあとの測り直し(reprime)

`--prime`(画像を読み込み済みにする準備)が JSON 方式に効いていなかった不公平を PR #20 で直したあと、F1〜F3(最終の取り直し)と S1〜S9(小型モデル)を、**準備なし・準備あり**の2条件で測り直した。数値は各実行の `runs/<実行>/cases.csv`(と `run.json`)から計算したもの(元画像 N=31、派生の `-strip` を除く。失敗の行数だけ全35ケース)。旧測定の集計は [`../final/summary.md`](../final/summary.md)・[`../small/summary.md`](../small/summary.md) に、そのまま残している。

## 1. 条件

- **何が不公平だったか**: 修正前の `--prime` は、選択式の system 文で準備リクエストを送っていた。JSON 方式の先頭(system 文が違う)には一致せず、JSON だけ画像の読み込みが判定時間に含まれていた(選択式・束ね質問は読み込み済み)。精度には影響しない。PR #20(`--prime` を方式ごとの準備にする)で、方式ごとに自分の質問形式で準備するようにした。修正前の `--prime` 付き実行(E9/E7/E7e、最終の取り直し F1〜F3、小型 S1〜S9)の「JSON 対 選択式/束ね」の時間比較は公平ではなかった。
- **準備なし**(`--prime` なし。`run.json` の `prime=false`): 各方式が画像の読み込みを判定時間に含む。「初めて見る画像」の実用条件。
- **準備あり**(`--prime`。`run.json` の `prime=true`、`prime_scope=per_mode`): 各方式の判定の直前に、その方式の準備を送る。準備の時間は `prime_ms` として別に記録し、判定時間(`classification_wall_ms`)には含めない。「画像を読み込み済み」の条件。
- 繰り返しは**各条件1回**(`temperature=0` で判定は決定的。前回の3回測定では、判定は3回とも完全一致し、時間の標準偏差は 2〜59 ms だった。この程度のばらつきは実行環境の揺らぎ(リアルタイム OS ではないため)によるもの。今回は1回なので、数十 ms 程度の差は区別できない)。
- 共通(全60実行の `run.json` で一致): データセット v1.0.0(`dataset/manifest.jsonl` SHA256 `941faf84f0c1e3f027748766b6ce2ec4181cc8749b0c1ad70ec8113b528baab0`)、taxonomy 0.4.1、JPEG(quality 90)、`--warmup 1`、`--axis-concurrency 1`、`http://127.0.0.1:1235/v1`。モデル・サーバー・回a/回b の構成は最終の取り直し(F1〜F3)・小型(S1〜S9)と同じ(F1 Qwen3.5 9B 改造版、F2 同 未改造版、F3 Gemma 4 12B 改造版。回a: 1軸ずつ確認オフ・JSON・束ね rank、回b: 1軸ずつ確認オン・束ね Y/N)。実行環境は `doc/experiments/runtime/` の JSON。
- **コミット(各 `run.json` の `tool_commit` の記録)**:
  - F1〜F3(準備なし12実行・準備あり12実行): `07086c09c591a5adf07a60fb0e28a681df2b296c`(PR #20 を main に取り込んだコミット `07086c0`)、dirty=False。
  - S1〜S9(準備なし18実行・準備あり18実行): `b7690853ae0ca752bff5e6659a151e06e4d5ab91`(ブランチ `exp/reprime`)、dirty=False。`07086c0` との差は `scripts/run_small_matrix.sh` だけ(`PRIME`・`OUT` を環境変数で切り替え可能にした。`git show --stat b769085`)。
- **実施日時(UTC、`progress.log`)**: 準備なし→準備あり の順。F は、準備なしの F1 長辺1024 の2実行(2026-09-29 15:50:11〜15:55:58)、準備ありの F1 長辺1024 の2実行(15:55:59〜16:01:54)、残りの準備なし(16:02:31〜16:41:15)、残りの準備あり(16:41:15〜17:25:59。完了済みの2実行は skip)の順。S は準備なし 17:27:03〜17:57:59、準備あり 17:57:59〜18:30:55。全60実行の終了コードは 0(`progress.log` の `done ... exit=0`)。
- **一次資料の置き場**: `final_noprime/`・`final_prime/`(F1〜F3。各 `runs/<実行>/` に `run.json`・`cases.csv`・`summary.md`、それに `progress.log`)、`small_noprime/`・`small_prime/`(S1〜S9。同じ構成と `S*_probe.log`)。個人のパスは含まれていない(確認済み)。

## 4. 観察
